# Source-grounded graph ingestion

Use these steps when the learner supplies notes, a document, an image, a recorded observation, or conversation-derived understanding. The global graph is a body of provisional domain claims. A source claim is not evidence that the learner knows it.

1. Read the relevant source accurately. For photographs, retain the original with `upload_attachment` through the MCP App, then inspect it with `inspect_attachment` if the host supports image tool responses. For PDFs, use a host-supported PDF reader, preserve page labels in the extracted text, and retain the original document when possible. Never invent an OCR transcript or source quotation.
2. Use `ingest_source_text` with `label`, `kind` (`document`, `conversation`, `notes`, `web`, or `observation`), `mime_type` (`text/plain` or `text/markdown`) and the actual extracted `text`. The server stores up to 2 MiB of UTF-8 source text per invocation and splits it into auditable spans.
3. Call `next_extraction(source_id)`. If it returns `action=complete`, stop. If it returns `action=audit`, inspect the saved proposals; do not silently generate new findings for an already pending span. If it returns `action=extract`, read that exact content.
4. Propose each independently meaningful proposition using `propose_extraction(span_id, claims, chains)`. Each claim requires a precise statement, contextual scope, domain and **verbatim quotation from the supplied span**. A multi-premise reasoning chain references zero-based indexes of candidate claims; it must distinguish entailment from non-deductive support, definitions, and models. Do not label an inference deductive merely because it is plausible.
5. Independently audit source faithfulness, context, proposition identity, and the explanatory link. Use `get_reasoning_graph`/`get_proposition` to look for existing identities. For `audit_extraction`, give exactly one indexed decision per claim (`accept`, `reuse` with an existing ID and explicit reason, or `reject`) and one indexed decision per chain. The store checks the original source, span fingerprint, and quoted passages again before merge. A known text's presence in a source is not confirmation of its truth. Mark uncertain material provisional.
6. If extraction is inaccurate, call `reject_extraction` and correct the proposal; a rejected span can be proposed again. Do not discard the source. If a statement is contradicted by stronger material, preserve the claim and mark it `disputed` through `review_proposition` rather than erasing the conflict.
7. After a valid merge, repeat `next_extraction` for uncovered spans only. Save literal learner or tutor exchanges using `append_learning_event(session_id, origin_id, role, content)` with a stable, unique origin ID for each actual message. The event becomes an extractable source span with its role and event ID; avoid inventing messages to fill the record.
8. At teaching time, prefer `search_knowledge` for indexed passages or `search_learning_sources` for exact fragments; verify quoted evidence through `get_proposition` or the source itself. If search does not return relevant evidence, say so rather than fabricating citations.

### Source integrity

Never automatically assign mastery when a proposition or chain is extracted or source-reviewed. A source quote supports an **attribution**, not necessarily the source's correctness. Knowledge claims are created provisional and can be disputed independently. Before labeling a reasoning chain reviewed, review the conclusion and each jointly required premise, check its source scope, and use `get_reasoning_chain` to inspect provenance and current blockers. A later dispute can suspend an old review; `review_active` is a current evidence gate, not a proof certificate. Interactions with the model are host-initiated: the Go server does not make hidden inference calls or run autonomous extraction while the user is away.

### Explicit deductive checks

For a chain whose relation is `entails`, first inspect every premise and the conclusion with `get_reasoning_chain` and `get_proposition`. Supply `check_reasoning_entailment` with the chain ID and a `formalization` object: `premises` maps **every** required proposition ID to its propositional formula; `conclusion` is the conclusion formula; `atoms` maps each uppercase atomic symbol to its intended meaning; and `scope` records the assumed context. For example, `P -> Q` and `P` entail `Q`. Supported syntax: uppercase atoms, `!`, `&`, `|`, `->`, and parentheses, with negation strongest, conjunction before disjunction, and right-associative implication. The bounded checker permits at most 12 distinct atoms, 16 premises and 384 bytes per formula. It enumerates every truth assignment rather than relying on a model to invent a proof.

Interpret `valid_on_formalization` only as an exhaustive propositional result for the **specified formulas**. `counterexample_found` provides an assignment making all premises true and the conclusion false. `inconsistent_premises` means the premises admit no joint truth assignment; do not invoke explosion as evidence of a sound explanation. Individually redundant premises can each be removed while preserving logical entailment, but these removals need not work simultaneously. Persisted checks are associated with a snapshot of the exact proposition wording and can become stale. No tool verifies that `P`, `Q`, or a composed formula accurately represents the corresponding source text. A model-written translation must be critically examined for concealed assumptions, quantifiers, empirical uncertainty, and scope changes. Deductive proof checking does not extend automatically to `supports`, `defines`, `models`, science, history, or learner mastery.

For an auditable translation judgment, call `get_proposition` for **every** premise and the conclusion, inspect the original span content, and use the returned `source_span_id` and exact `quoted_text`. Supply `record_translation_review(check_id,review)` with one anchor per claim, an explicit alignment judgment and rationale, the reasoning domain, and any relevant assumptions or limitations. Use `get_translation_reviews` to inspect disagreements and the current integrity status. In empirical or model-dependent arguments, state the measurement and modeling assumptions and the methods needed to validate them; in quantified or mathematical arguments, state the missing proof obligations; in historical arguments, state the source-critical limitations. The review is a recorded interpretation, not independently authenticated evidence of truth or exact semantic correspondence. Do not promote it into learner mastery.

## Conflicting sources and models

If two grounded propositions appear incompatible, use `record_proposition_dispute` to identify the exact pair and evidence for the disagreement. Do not silently delete one claim or merge away the conflict. Use `resolve_proposition_dispute` only after the scope, assumptions and source evidence are examined; `different_contexts` is appropriate when different physical theories or historical perspectives legitimately make different claims. An unresolved contradiction is not a learner misconception, and resolving it never awards mastery.
