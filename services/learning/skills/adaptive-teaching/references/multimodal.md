# Multimodal work and original evidence

Photographs and original documents are an ordinary way to submit work in Adaptive Teaching, whether the subject is mathematics, electrical engineering, art, language, biology, history or practical craft.

- In compatible MCP App clients, the learner opens a saved problem or learning session, chooses one or more files and uses **Save originals**. The browser sends the original bytes to `upload_attachment`, associated with the specific problem, session, or source. Text drafts are a separate record. The interface currently caps each upload at 5 MiB; the storage API caps files at 10 MiB.
- Supported originals: PNG, JPEG, WebP, HEIC, PDF, UTF-8 text and Markdown. The backend checks a file's signature against the supplied MIME; unsafe SVG or executable file types are not admitted. Original files and interpretations reside in private SQLite storage, not GitHub.
- Use `list_attachments` to locate work. `inspect_attachment` returns original images as MCP image content visible to a capable host model. `get_attachment(include_original=true)` returns original base64 only when needed. Both original-byte retrieval paths verify the stored size and SHA-256 digest; a mismatch is a storage-integrity error and the original must not be presented as intact. Metadata-only reads do not verify the bytes. A PDF stored as bytes does not mean the host has interpreted its pages; use an authorized document reader or a faithfully extracted text source.
- Always distinguish *what the image visibly shows*, *what you infer from it*, and *what the learner demonstrated*. Use `annotate_attachment` with `model_interpretation` and an uncertainty note where ambiguous; use `learner_transcription` or `verified_transcription` only when appropriate. The model must not guess illegible symbols, resistor colors or instrument readings.
- If a ChatGPT host cannot present file selection or image content, state the limitation. Do not claim an image was processed simply because its file ID exists.
- The service has no built-in identity authentication. Do not expose the MCP endpoint or private attachments without a verified owner-authenticated gateway. The public repository must never contain real learner images, photographs, assessment records, or databases.
